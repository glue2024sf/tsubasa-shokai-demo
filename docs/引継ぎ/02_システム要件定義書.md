## 1. システム概要

- Sales Cloud（3ユーザー）上に、**問い合わせ → 商談 → 見積 → 受注 → 請求 → 入金消込** の一連を載せる。
- 帳票（見積書・請求書・納品書・出荷指示書）をSF内でPDF出力。
- 経営・営業・事務の3ロール向けダッシュボードで可視化。
- 会計連携なし（パターン②: SF内完結）。

凡例（実装状況）: ✅ デモ実装済 ／ ⚠️ 一部・要対応 ／ ❌ 未対応・要確認（実Org構築は別途）

## 2. データモデル

### 2-1. 採用オブジェクト

| 種別 | API名 | 用途 |
| --- | --- | --- |
| 標準 | `Lead` | 見込客（サンプル送付管理含む） |
| 標準 | `Account` | 取引先（法人単位／配送先住所×3） |
| 標準 | `Opportunity` | 商談（明細・受注・出荷・入金を集約） |
| 標準 | `Product2` / `PricebookEntry` | 商品マスタ |
| 標準 | `OpportunityLineItem` | 商談明細（商品×単価×数量） |
| 標準 | `Task` / `Event` | 活動（電話／メール／FAX） |
| カスタム | `Invoice__c` | 請求書（商談100%で1対1生成） |
| カスタム | `BankAccount__c` | 振込先口座マスタ |

> **配送先住所の設計判断**: 最大3で固定のため、`Account` に項目3セット（宛名＋住所×3）で実装。子オブジェクト化（`ShippingAddress__c`）は将来の柔軟性が必要になった時点で再検討。

### 2-2. 項目定義

#### Lead（リード）
| 項目 | 型 | 備考 |
| --- | --- | --- |
| Company（法人名） | 標準 | 必須 |
| Address / Phone / Industry | 標準 | 業種は選択リスト（農業／イベント／物流／建設／その他 ※候補要確定） |
| LeadSource（流入経路） | 標準 | FAX-DM／Meta広告／紹介／その他 |
| `SampleSent__c` | チェック | サンプル送付済 |
| `SampleSentDate__c` | 日付 | サンプル送付日 |
| Description（備考） | 標準 | |

#### Account（取引先）
| 項目 | 型 | 備考 |
| --- | --- | --- |
| Name（法人名） | 標準 | 必須 |
| BillingAddress | 標準 | 請求書送付先 |
| Phone / Industry | 標準 | |
| `ShippingName1〜3__c` | テキスト | 配送先宛名×3 |
| `ShippingAddress1〜3__c` | 住所/テキスト | 配送先住所×3（宛名とセット運用） |
| `SampleSent__c` / `SampleSentDate__c` | チェック / 日付 | リードと両方に保持（重複送付防止） |
| Description（備考） | 標準 | |
| （取引先コード） | テキスト/自動採番 | **採番ルールで使用** → §6 採番 |

#### Opportunity（商談）
| 項目 | 型 | 備考 |
| --- | --- | --- |
| Name（案件名/商談番号） | 標準 | **自動採番** → §6 |
| AccountId / StageName / CloseDate | 標準 | フェーズは §5、CloseDate=受注（予定）日 |
| Amount | 標準 | 明細集計 |
| `Subtotal__c` / `ShippingFee__c` / `Discount__c` | 通貨 | 明細小計／送料／値引 |
| `Tax__c` | 通貨/数式 | **外税10%の税額**（⚠️ 要追加 / §6） |
| `Remarks__c` | ロングテキスト | 備考 |
| `ShipmentDate__c`（出荷日実績） / `ShipmentScheduledDate__c`（出荷予定日） | 日付 | 予定日は未来日入力可 |
| `ArrivalScheduledDate__c`（着予定日） / `ArrivalDate__c`（着日実績） | 日付 | **着日実績の入力で出荷予定リストから外れる** |
| `ShipmentCarrier__c` | 選択リスト | 運送会社（西濃運輸／福山通運 等） |
| `TrackingNumber__c` | テキスト | 追跡番号 |
| `Weight__c` | テキスト/数値 | 重量 |
| `InvoiceIssuedDate__c` | 日付 | 請求書発行日（生成時コピー） |
| `PaymentDate__c` | 日付 | 入金日 |
| `UnpaidDays__c` | 数式 | `IF(ISBLANK(PaymentDate__c), TODAY()-InvoiceIssuedDate__c, 0)` |
| `IsOverdue__c` | 数式 | `UnpaidDays__c >= 60` |

#### OpportunityLineItem（商談明細）
- 標準項目で網羅: `Product2Id` / `UnitPrice` / `Quantity` / `TotalPrice`。備考用に `LineDescription__c`（任意）。

#### Invoice__c（請求書）
| 項目 | 型 | 備考 |
| --- | --- | --- |
| Name | 自動採番 | **見積番号=案件番号方針** → §6 で要整合 |
| `Opportunity__c` | 参照/主従 | 商談 |
| `Account__c` | 参照/数式 | 取引先 |
| `IssuedDate__c` | 日付 | 発行日 |
| `Subtotal__c` / `ShippingFee__c` / `Discount__c` / `Tax__c` / `TotalAmount__c` | 通貨 | 商談からコピー（**税額含む**） |
| `BankAccountPrimary__c` / `BankAccountSecondary__c` | 参照（BankAccount__c） | 表示口座①② |
| `Status__c` | 選択リスト | 未送付／送付済／入金済 |

#### BankAccount__c（振込先口座マスタ）
| 項目 | 型 |
| --- | --- |
| Name / `BankName__c` / `BranchName__c` | テキスト |
| `AccountType__c` | 選択（普通／当座） |
| `AccountNumber__c` / `AccountHolder__c` | テキスト |
| `IsActive__c` | チェック（表示制御） |
| `DisplayOrder__c` | 数値（並び順） |

## 4. 自動化（Flow）

| Flow | トリガ | 処理 | 状況 |
| --- | --- | --- | --- |
| **F1 請求書自動生成** | Record-Triggered（Opportunity, After Update, StageName=受注100%） | `Invoice__c` 生成・商談から項目コピー・`IssuedDate__c=TODAY()`。あわせて納品書・出荷指示書も生成 | ❌ 実Org要構築（**最重要**） |
| F2 入金消込 | Opportunity の `PaymentDate__c` 入力時 | 関連 `Invoice__c.Status__c="入金済"` | ❌ 要構築 |
| F3 未入金アラート | Scheduled（日次） | `UnpaidDays__c>=60` をフラグ／DB表示 | ❌ 要構築（数式＋DBで代替可） |

## 6. 採番・税・帳票ルール（6/2合意の反映）

### 採番
- ルール: **年度 + 取引先コード + 連番**（年度切替でリセット）。
- **見積番号 = 案件番号**（商談番号と一致させる）。
- ⚠️ 現行デモは `OPP-2026-0030` / `INV-2026-0008` の「年度+連番」型で、**取引先コードが未反映**かつ**見積番号と商談番号が別採番**。実Orgの自動採番（Auto Number）設計で要整合。

### 税
- **外税10%**・四捨五入。軽減税率対象なし。
- ⚠️ 現行帳票は「合計（税込）」表記で**外税10%の税額行が無い**。見積・請求書に税額明細行の追加が必要（最重要修正）。

### 帳票（4種）
| 帳票 | 主要項目 | ボタン | 状況 |
| --- | --- | --- | --- |
| 見積書 | 宛先／見積No／**有効期限（発行+1ヶ月）**／明細／合計／備考／ロゴ／角印 | 商談詳細「見積書PDF出力」 | ⚠️ ロゴ・角印が素材待ち |
| 請求書 | 取引先・自社住所/電話／**インボイス番号**／**振込先2口座**／明細／金額／角印 | 請求書「請求書PDF出力」 | ⚠️ 実値・素材待ち |
| 納品書 | 明細＋配送先住所・運送会社・重量 | 受注時自動生成 | ✅ デモ |
| 出荷指示書 | 配送先・重量・運送会社・追跡番号 | 受注時自動生成 | ✅ デモ |

- 帳票エンジン候補: **A. OPROARTS（国産・角印対応・◎）** または **D. PDFBuilder（国産・低価格・○）**。本番リリース時期と角印必須を踏まえ国産GUIテンプレを推奨。**実Orgでの選定・セットアップは未着手**。

## 9. データ移行

| データ | 件数（概算） | ソース | 移行先 |
| --- | --- | --- | --- |
| 顧客（法人） | 約3,000件 | 事務コンCSV | `Account` |
| 過去取引 | 3,000〜5,000件 | 事務コンCSV | `Opportunity`（閉じた状態で投入） |
| 商品マスタ | 要確認 | 事務コンCSV | `Product2` |
| 振込先口座 | 2件 | 手動 | `BankAccount__c` |

- クレンジング: **法人名の表記ブレ（「株式会社」「（株）」「(株)」）を統一**。重複は移行後にレポートで検知。
- **事務コンからの抜き出しは1回のみ**（制約）。チューニング期間バッファを確保。
- タイミング: 構築はサンプルデータ → リリース直前に本番抽出・クレンジング・投入・確認。

## 10. 非機能・前提

- 対象ユーザーはITに不慣れ → **画面はSalesforce標準UIに寄せ、操作を単純に**。簡易マニュアル＋レクチャーを提供。
- 外部公開なし・社内利用のみ。
- 本番リリースは事務コン9/30解約に間に合わせる（最優先制約）。
